# RC-005.3B Release Container Trust Evidence

## 1. Purpose

RC-005.3B proves that the USOP backend release container preserves the
production License verification trust boundary established by RC-005.3A.

The release image must contain the production public verification key while
remaining completely free of production private signing material.


## 2. Frozen Input Baseline

RC-005.3B validation was performed from:

`3e00c3a391fa06fb6968166bbb808a7b439bf2e2`

RC-005.3A provisioned the first production License signing authority trust
entry:

`usop-license-root-2026-01`


## 3. Production Public-Key Identity

The release-controlled public verification key is:

`backend/app/security/trusted_license_keys/usop-license-root-2026-01.public.pem`

The ceremony-pinned DER-encoded public-key SHA-256 fingerprint is:

`dbfd22405ac8ecf101ef7291143c86046f7405e5cf41e656362bc27168997d66`


## 4. Release Image Build

The backend release image was built using:

`backend/Dockerfile.release`

`usop:rc-005.3b2`

Observed image identifier:

`sha256:b9ee82816c590e65906876f5015a281138fd99a44dfa51ea696dc54783dfa655`

The Docker build context was limited to the backend directory.


## 5. Release Image Trust Verification

The release image was inspected directly.

Validation proved:

- the production public verification PEM exists inside the release image;
- the PEM contains public material only;
- runtime trust contains exactly `usop-license-root-2026-01`;
- the container executes as a non-root user;
- no private-key PEM markers exist beneath `/app/app`;
- the expected signing-key identifier is available to the runtime.


## 6. Containerized License Validation

A temporary Beta License was issued outside the container using the active
production License Authority.

Signing key:

`usop-license-root-2026-01`

Only the signed License artifact was mounted read-only into the release
container.

The production private signing key was not mounted, copied, or otherwise made
available to the container.

The release container successfully validated the signed License using only its
release-controlled public verification trust material.

Observed runtime trust:

`('usop-license-root-2026-01',)`

Observed License signing key:

`usop-license-root-2026-01`


## 7. Private-Key Boundary

The production private signing key remained outside:

- Git;
- the Docker build context;
- the release image;
- the signed License artifact;
- the running validation container.

The test License artifact contained no private-key material.


## 8. Temporary Artifact Handling

The temporary authority-signed License used for container validation was
deleted after successful validation.

The repository worktree remained clean after container testing.


## 9. Result

RC-005.3B demonstrates that the actual USOP backend release image preserves
the production License trust architecture.

The release image:

1. contains the approved production public verification key;
2. trusts the production signing-key identifier;
3. contains no production private signing material;
4. validates a License signed by the production License Authority;
5. requires no customer-controlled trust injection.

Status:

`PASSED`
